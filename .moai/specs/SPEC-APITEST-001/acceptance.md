# SPEC-APITEST-001 인수 기준 (Acceptance Criteria)

## 1. 인수 시나리오 (Given-When-Then)

### AC-1: 유효한 키 빠른 검증 성공

- **Given** 사용자가 ChatGPT 카드에 유효한 OpenAI API Key를 입력하고 제공자를 활성화한 상태이며, 모드 토글이 "빠른 검증(quick)"으로 설정되어 있다
- **When** 사용자가 해당 카드의 "테스트" 버튼을 클릭한다
- **Then** 시스템은 `app/api/test-key/route.ts`로 `{ provider:'chatgpt', mode:'quick' }` POST 요청을 전송하고, 서버는 OpenAI `GET /v1/models`를 호출하여 2xx 응답을 받는다
- **And** 카드 내에 키 유효성 배지가 "유효(success)"로 인라인 표시된다
- **And** quick 모드이므로 모델 체크박스는 비활성 상태이고 모델별 결과 행은 표시되지 않는다

### AC-2: 유효하지 않은 키 → 에러 배지

- **Given** 사용자가 Gemini 카드에 잘못된 API Key를 입력하고 모드가 "빠른 검증(quick)"이다
- **When** 사용자가 "테스트" 버튼을 클릭한다
- **Then** 서버의 `ListModels` 호출이 401/403을 반환하고, 응답은 `{ keyValid:false, keyError: ... }`이다
- **And** 카드 내 키 유효성 배지가 "무효(fail)"로 표시되고 에러 메시지가 노출된다
- **And** 키 값은 결과 화면이나 로그에 평문으로 출력되지 않는다

### AC-3: 핑 모드 다중 모델 혼합 성공/실패

- **Given** 사용자가 Claude 카드에 키를 입력하고, 모드를 "실제 핑(ping)"으로 설정한 뒤 3개 모델 중 2개(예: `claude-sonnet-4`, 존재하지 않는/접근불가 모델)를 체크했다
- **When** 사용자가 "테스트" 버튼을 클릭한다
- **Then** 서버는 체크된 각 모델에 대해 `model.invoke("Hi")`를 동시성 상한 내에서 수행하고 `Promise.allSettled`로 결과를 수집한다
- **And** 카드 내에 모델별 행이 표시되며, 성공 모델은 success 배지 + 지연시간(ms) + 응답 미리보기를, 실패 모델은 fail 배지 + 에러 메시지를 보여준다
- **And** 일부 모델 실패가 다른 모델의 성공 결과 표시를 막지 않는다(부분 실패 허용)

### AC-4: 네트워크 오류 / 타임아웃 엣지 케이스

- **Given** 제공자 엔드포인트가 응답하지 않거나 호출이 타임아웃 임계값을 초과한다
- **When** 사용자가 "테스트" 버튼을 클릭한다
- **Then** 해당 호출은 `AbortController`에 의해 중단되어 실패로 처리된다
- **And** 카드의 키 배지/모델 행이 실패 상태로 표시되고, `sonner` toast로 네트워크/타임아웃 오류가 사용자에게 안내된다
- **And** 429(rate limit) 응답의 경우 일반 실패와 구분되는 메시지로 표시된다

## 2. 진행 중 상태 검증 (State)

- 테스트 진행 중 "테스트" 버튼은 비활성화되고 `Loader2` 스피너가 표시된다.
- 진행 중 동일 카드의 중복 실행은 차단된다.
- 제공자 `enabled`가 false이거나 `apiKey`가 비어 있으면 "테스트" 버튼은 비활성화된다.

## 3. 성능 기준 (Performance Criteria)

- **호출당 타임아웃**: 단일 제공자/모델 호출은 최대 15초(권장) 내에 응답 또는 중단되어야 한다.
- **동시성 상한**: 핑 모드에서 다중 모델 호출 동시 실행 수는 최대 3개로 제한한다(초과 모델은 큐잉).
- **응답 미리보기 길이**: 모델 응답 미리보기는 최대 200자로 절단하여 표시한다.

## 4. 품질 게이트 (Quality Gates)

- 모든 제공자 호출이 서버 사이드(`app/api/test-key/route.ts`)에서만 실행됨을 코드 리뷰로 확인(클라이언트에서 외부 도메인 직접 호출 없음).
- API Key가 응답 본문, 클라이언트 상태 결과 표시, 서버 로그 어디에도 평문으로 노출되지 않음.
- DB 변경 없음: `src/db/schema.ts` 및 마이그레이션 파일에 변경이 없음.
- TypeScript strict 통과, `any` 미사용, Zod 요청 검증 적용.
- 핵심 어댑터(quick/ping) 단위 테스트 및 4개 인수 시나리오(AC-1~AC-4) 검증.

## 5. 완료 정의 (Definition of Done)

- AC-1 ~ AC-4 시나리오가 모두 통과한다.
- 빠른 검증/실제 핑 두 모드가 모두 동작하며 결과가 카드 내 인라인으로 표시된다.
- 새로고침 시 결과가 소실됨(영속화 없음)이 확인된다.
- 진행 중 상태(버튼 비활성/스피너/중복 차단)와 비정상 동작(무효 키/네트워크/타임아웃/rate limit/부분 실패)이 명세대로 처리된다.
